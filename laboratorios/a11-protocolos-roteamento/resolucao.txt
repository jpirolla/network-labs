HTTP - Visão Geral
HTTP não persistente:
– Um objeto é enviado sobre uma conexão TCP.
– HTTP/1.0 utiliza HTTP não persistente.
HTTP persistente:
– múltiplos objetos podem ser enviados sobre uma
conexão.
– TCP entre o cliente e o servidor.
– HTTP/1.1: conexões persistentes em modo padrão.
– HTTP/2.0: Google, minification, prevê futuros requests
Tipos de conexões HTTP
Teste com HTTP1.1 e 2.0:
curl --http1.1 -w "HTTP1.1: %{time_total}s\n" -o /dev/null -s
https://www.google.com
curl --http2 -w "HTTP2: %{time_total}s\n" -o /dev/null -s
https://www.google.com
Tipos de conexões HTTP
• Persistente sem paralelismo:
• cliente emite novas requisições apenas quando a
resposta anterior for recebida.
• Persistente com paralelismo:
• padrão no HTTP/1.1;
• cliente envia requisições assim que encontra um
objeto referenciado.
• Requisições sequenciais na mesma conexão TCP
• Problema: causa o problema Head of Line Blocking
HTTP persistente
• Uma única conexão TCP transporta várias requisições
em paralelo
• Requisições fora de ordem
• Se um objeto demorar (imagem grande), outra requisição
é atendida antes de terminar a anterior
• Servidor responde fora de ordem
• No HTTP 1.1, reduz-se o tempo para criar múltiplas
conexões TCP
HTTP com Multiplexação
• No HTTP 1.1, cada conexão TCP lida com uma requisição
por vez
• Mesmo que haja várias conexões TCP (máximo de 6)
• No HTTP 2.0, uma única conexão pode lidar com várias
requisições ao mesmo tempo
• Sem bloqueio
• No HTTP 2.0, não há necessidade de múltiplas conexões
TCP
